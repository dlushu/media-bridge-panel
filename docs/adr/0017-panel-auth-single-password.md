# ADR-0017 面板门禁：单密码，不是用户体系

- 状态：已采纳
- 相关：[auth.js](../../server/core/auth.js) · [SECURITY.md](../../SECURITY.md)

## 背景

面板默认监听局域网地址，任何能访问该地址的人都能看到源配置、Emby 账号与播放链路。
需要一道门禁，但不需要（也不应假装拥有）完整的用户体系。

## 决定

实现**单密码门禁 + 签名会话**：登录后 30 天内免登录，密码以 scrypt 哈希保存。

保护范围：

| 类别 | 处理 |
|---|---|
| 面板自身接口（`/api/sources*`、`/api/agg*`、`/api/modules*`、`/api/panel*`、`/api/logs` 等） | 要求登录 |
| 被代理的源配置页（`/website*`） | 要求登录 |
| `/api/auth/*` | 放行（否则无法登录） |
| `/api/emby/*` | 放行 —— 这些端点有自己的 AccessToken 校验；面板门禁拦截它们会让所有客户端立即断开，容器健康检查也走该路径 |
| 静态文件（首页 / JS / CSS） | 放行 —— 只是外壳，不含数据，登录界面本身依赖它 |

其它约定：

- 默认密码 `123456`；首次启动写入的是其 scrypt 哈希，不是明文。
- **修改密码会使所有既有会话立即失效**（会话签名中包含密码指纹）。
- 试错节流：同一 IP 连续失败 5 次锁定 60 秒，面板日志中可见失败与锁定记录。
- 凭证存放于 `data/auth.json`，**不放在 `data/settings/`** —— 该目录会被「配置备份」原样导出，
  密码哈希与会话密钥不应走那条路径。删除该文件即恢复默认密码。

## 理由

目标明确：挡住"局域网里随手打开面板的人"。
引入多用户、权限分级会显著增加实现面，却不能改变"HTTP 明文传输密码"这一根本限制 ——
真正的边界应由反向代理与 HTTPS 提供。

## 备选方案

- **不做门禁**：面板直接暴露源配置与 Emby 账号。
- **完整用户体系**：成本高，且在当前部署形态下收益有限。

## 后果

- 面板默认是明文 HTTP，密码在链路上是明文，除非前置 HTTPS 反向代理。
- **不要把面板直接暴露到公网**；需要外网访问时只发布面板端口并置于反向代理之后
  （见 [SECURITY.md](../../SECURITY.md)）。
- 忘记密码的处理方式：删除 `data/auth.json` 后回到默认密码。
