# ADR-0003 挑片判据：本地打分，不做 TMDB 反查

- 状态：已采纳（取代早期的"精确同名 + TMDB 别名回退"）
- 相关：[match.js](../../server/modules/agg/match.js) · [emby-compat.md](../emby-compat.md) · [0004](0004-no-same-site-dedup.md) · [0005](0005-continuation-fetch.md)

## 背景

早期判据是：站源条目与目标片名**归一化后完全相等**才算命中；一条都没有时，把候选名交给 TMDB
反查 `tmdbId`，用"搜索结果里含该 id"作为同一作品的证据。

这个判据的失败点在**输入侧**：站源标题通常包含更新话术与画质标注，例如
`斗破苍穹年番4更211[2025][动漫]`、`…4K臻彩中字【1GB/集】更211集`。
这类文本直接用于检索无法命中，于是既没有同名条目、也没有别名命中，最终不返回任何线路 ——
在客户端里的表现是"条目存在，点开却没有版本"。

## 决定

在**搜索阶段**对每条结果打分，按分数排序并设两道闸门：

- 权重：名字 `0.7` · 季集 `0.2` · 年份 `0.1`；**缺项不计入分母**（源里常常没有季集或年份）。
- 名字分：清洗后相等 `1.0`；主干同名 + 受控限定词 `0.95`；其余按最长公共子序列相似度。
  清洗剥掉更新话术、画质与字幕标注、体积、年份、噪声括号、分类后缀。
- 闸门一（硬拒）：清洗后没有公共主干，或相似度 < `0.5`，直接出局。
- 闸门二（分数线）：`matchMinScore` 默认 `0.85`；**填 0 表示不按分数线筛选**，
  此时只按分数排名取前 `matchMaxItems` 条。

判据只实现一次，位于 `server/modules/agg/match.js`，面板搜索与客户端请求共用。

## 理由

- 不依赖外部服务：源站标题的脏数据不需要外部数据源参与清洗，阈值调整立即生效。
- 可解释：每条结果带 `score` 与 `matchReason`，未命中的带原因（低分 / 超上限 / 名字不过闸）。
- 可复现：面板「聚合搜索」页可以直接看到同一套判据给出的结果。

## 备选方案

- **保留 TMDB 反查**：输入脏则失效；且把可用性绑在外部服务的连通性上（该项目运行环境中该链路不稳定）。
- **人工绑定表**（`tmdb id → 站点 vod_id`）：准确率最高，但需要人工维护，作为后续补充而非主判据。

## 后果

- 分数只用于**排序与闸门**，不等于"确实是同一部作品"。判定错误时调整分数线或条数即可。
- 阈值与条数存放在 `data/settings/agg.json`（`matchMinScore` / `matchMaxItems`），
  可在「聚合设置 → 聚合参数」修改，也可在单次请求中覆盖。
- 站源 `/search` 的条目只有 `vod_id` / `vod_name` / `vod_pic` / `vod_remarks`，
  **没有类型也没有年份字段**，因此"类型不符则排除"在搜索阶段无法实现，闸门只能建立在名字相似度上。
