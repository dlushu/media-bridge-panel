# ADR-0013 图片端点：签名 tag + 本地索引

- 状态：已采纳
- 相关：[0009](0009-unauthenticated-empty-responses.md) · [emby-compat.md](../emby-compat.md)

## 背景

Emby 的 `BaseItemDto` **没有图片直链字段** —— 客户端一律自己拼接
`Items/{Id}/Images/{type}?tag=…` 来取图，因此图片地址必须编码在 `tag` 里。
同时该端点必须**豁免 token**（客户端携带凭证的方式不统一，若要求 token，部分客户端的图片会直接失败），
于是它天然有变成开放图片代理的风险。

早期还存在一条"按条目 Id 反查 TMDB 拿图"的兜底路径，实现绕了两个弯，
并且会随片库规模**线性**消耗上游配额。

## 决定

- `tag` 形如 `cpimg.<base64url(URL)>.<签名>`；端点校验签名，签名不符或篡改一律返回 `404`。
  签名密钥 `imageKey` 在首次使用时自动生成。
- 维护**本地图片索引**：生成 tag 时顺手记录（此时 URL 已在手边，成本为零），
  请求没带 tag 时查该索引。
- 索引**按"模块给出的条目 id"记录**，不依赖 TMDB 坐标 —— 使用自定义 id 的插件同样能取到图。
- 索引**只存相对路径**：写入时剥掉图床基地址，读取时按**当前**基地址拼回。
- 删除"按 Id 反查 TMDB"的兜底路径。

## 理由

- 豁免鉴权的端点必须自带防滥用手段，签名是最小成本的做法。
- 图片位置本来就在本项目手里，不需要反查上游；反查的代价随规模线性增长。

## 备选方案

- **不签名、依赖"只有知道 URL 的人能取"**：等于开放代理。
- **保留反查兜底**：需要额外的上游配额，且随规模线性放大。

## 后果

- 更换图床镜像**立即生效**，无需清理缓存（索引里存的是相对路径）。
- 实测记录：客户端对主图存在两类行为 —— 读取 `ImageTags.Primary` / `PrimaryImageTag`，
  或直接裸请求 `Images/Primary`。部分客户端在登录后 4ms 即请求图片，而列表响应需要 213ms 才返回，
  说明它使用的是**自己缓存的条目 Id**，本次返回的 DTO 并未参与。
  结论：这类客户端按设计不读主图的 tag；而 `Tag` 参数在官方定义中是可选的，该行为合规。
