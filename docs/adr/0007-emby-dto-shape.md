# ADR-0007 Emby 响应按真机 DTO 形状对齐

- 状态：已采纳
- 相关：[emby-compat.md](../emby-compat.md) · [emby/service.js](../../server/modules/emby/service.js) · [0008](0008-no-fabricated-data.md)

## 背景

客户端打开任何条目详情都失败（界面显示"网络错误或当前媒体库不存在该项目"，转圈后停止），
而服务端返回的是 `200`，且客户端拿到响应后**不再发出任何后续请求**。
这说明问题不在某个字段的取值，而在**整条响应无法解码**。

定位过程分三步：

1. 修好源、聚合确实拿到线路之后**仍然打不开** ⇒ 不是聚合层的问题。
2. 用真机 Emby 的响应作为模板替换后**立即正常** ⇒ 是 DTO 形状问题。
3. 按真机形状补齐后，**即使一条线路都没有、甚至只返回元数据也能渲染** ⇒ 客户端需要的是
   元数据字段的完整性与类型正确，而不是 `MediaSources` 本身。

## 决定

Emby 端点返回的 DTO **按真机（Emby 4.9.5）的形状对齐**：

- 补齐条目级结构性字段（`ParentId`、`DateCreated`、`Etag`、`SortName`、`PartCount`、`CanDelete` 等）。
- 补齐条目级线路派生字段（`Container`、`MediaStreams`、`Path`、`Size`、`Bitrate`、`FileName` 等）。
- 补齐 `MediaSource` 与 `MediaStream` 两级字段。
- **数组字段一律给 `[]`，不省略**。
- `People[].Id`、`Studios[].Id`、`GenreItems[].Id` 必须给出且类型正确（`GenreItems[].Id` 为数字）。
- `Etag` 使用内容哈希；`Path` 使用绝对 URL。

## 理由

客户端对 DTO 的解码是**整条通过或整条失败**。缺一个字段的代价不是"少显示一项"，
而是"这个条目完全打不开"，且失败发生在客户端内部，服务端日志上看不出原因。

## 备选方案

- **只给客户端明确需要的字段**：即本 ADR 之前的实现。表面上更"精简"，实际上会触发上述整条解码失败。
- **只对齐自己用到的类型（如电影）**：客户端的字段清单是共享的，逐类型对齐无法覆盖。

## 后果

- 字段清单以真机响应为模板维护；新增端点或字段时应参照同一份模板，不凭直觉精简。
- 与 [ADR-0008](0008-no-fabricated-data.md) 的边界：**结构字段必须齐**（哪怕是空数组或零值占位），
  但**不掌握其值的字段一律不填** —— 两者约束的对象不同。
