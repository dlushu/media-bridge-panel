# ADR-0002 emby 层进程内直调聚合层

- 状态：已采纳
- 相关：[ARCHITECTURE.md](../../ARCHITECTURE.md) · [0001](0001-module-layering.md) · [agg/api.js](../../server/modules/agg/api.js)

## 背景

按 [ADR-0001](0001-module-layering.md)，`emby` 层原本通过 HTTP 请求面板自身的 `/api/agg/*` 取详情与播放地址。
这条自调用会撞上面板自己的门禁：`core/auth.js` 对 `/api/` 前缀一律要求登录，而进程内自调用不带 cookie，
于是得到 `401`。表现为每条详情退化成"只回元数据"、播放链路中断，而日志里只留下
`UPSTREAM_HTTP http://127.0.0.1:<port>` 一行 —— `401` 发生在进入路由之前，连聚合层的请求日志都不会产生。

## 决定

`emby` 层直接 `require('../agg/api')` 调用聚合层，不走 HTTP。
`/api/agg/detail` 与 `/api/agg/play` 两个端点保留（供前端与外部调用），与 emby 层共用同一套编排。

## 理由

- 两层同进程，绕出去请求自己没有意义，反而引入鉴权、序列化、超时三重开销。
- 两条路径共用 `agg/api.js`，返回形状一致，不会随实现漂移。
- 避免为自调用新增一条鉴权旁路。

## 备选方案

- **给自调用加白名单或内部 token**：需要新增一条鉴权例外，且仍需序列化与超时处理。
- **让聚合层也校验面板会话**：等于把面板门禁的语义扩展到模块之间，边界更乱。

## 后果

- 聚合地址固定为本面板自身，「Emby → 连接设置」中不再提供该配置项。
- 其余跨模块调用（`agg → source`、面板 → 外部聚合源）仍走「地址 + HTTP」—— 那些地址可以位于其他机器。
- 两条路径的错误语义不同：路由层把失败翻成 HTTP 状态码，emby 层读 `error.code` / `error.message` 并写日志。
