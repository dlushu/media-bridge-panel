# ADR-0012 本地托管的源自动参与聚合

- 状态：已采纳
- 相关：[agg/service.js](../../server/modules/agg/service.js) · [agg/settings.js](../../server/modules/agg/settings.js)

## 背景

早期聚合用的源需要在「源列表」中逐个手动添加，包括面板自己托管的源。
但本地托管的源**没有固定地址**：它的监听端口在启动时确定，重启后可能变化。
任何把地址写进配置的做法都会在某个时刻指向过期端口。

## 决定

聚合源清单**每次实时计算**，由两部分合并：

1. **本地已部署的源** —— 名字取源自身的名字，地址取它**当前**的端口；不需要配置、不可删除，
   生命周期归「源托管」页管理；
2. **自定义源**（`agg.sources`）—— 用户填写的外部地址，可启用/停用、可删除。

并新增 `GET /api/agg/sources`：只返回清单、不做探测（毫秒级返回），供前端先渲染再后台探测。

## 理由

- 端口会变，落盘的地址必然过期；而"本机部署了哪些源"这个事实在运行时是确定的。
- 本地源的出现是"部署源"这个动作的副作用，不应再要求用户手动同步一次。

## 备选方案

- **把本地源地址写进聚合配置**：需要在每次端口变化时同步配置，且失败是静默的。
- **只允许手动添加外部源**：即早期实现，对最常见的用法（本机托管）反而最麻烦。

## 后果

- 前端「源列表」需要区分两类源：本地部署的显示运行状态与"去管理"入口，自定义源显示启停开关。
- 探测与清单拆成两个端点：「源列表」页先拿清单渲染，再并发探测各源站点。
