# ADR-0009 回空的端点不校验账号

- 状态：已采纳
- 相关：[emby-compat.md](../emby-compat.md) · [0008](0008-no-fabricated-data.md)

## 背景

Emby 端点默认校验 `AccessToken`，无 token 或 token 无效一律回 `401`。
但有一批端点在当前实现下**必然返回空**：观看历史类（`Items/Resume`、`Shows/NextUp`）、
`Studios`、`Items/Counts`，以及 `Filters=IsFavorite/IsPlayed` 与无法识别的查询参数。
对本项目而言这些响应没有任何可保护的数据，而客户端在不带 token 时请求它们会白吃 `401` ——
它本该拿到一个空列表。

## 决定

**回空的端点不校验账号**；**返回真实数据的端点照旧校验**（无 token 一律 `401`）。

需要的真实数据的端点包括：`Views`、`Items?ParentId=<本项目的库>`、条目详情、季与集列表。

"某个查询是否会返回数据"的判据收敛在**一处**（`service.itemsWillReturnData()`），
由路由层与 `service.getItems` 共用，避免两处判定漂移。

## 理由

对没有数据的响应做鉴权只产生失败，不产生保护。
把这类请求从 `401` 改为空列表，对客户端是可用性提升，对数据面没有影响。

## 备选方案

- **统一校验所有端点**：语义最一致，但会让部分客户端在首页/详情上出现无谓的错误。
- **统一不校验**：会让真实数据端点暴露，不可接受。

## 后果

- 需要显式维护"这个查询会不会返回数据"的判据，新增端点时必须先判定它属于哪一类。
- 图片端点同样豁免 token（原因不同：客户端携带凭证的方式不统一，要求 token 会让部分客户端的图直接失败），
  该端点依靠签名 `tag` 防滥用，见 [ADR-0013](0013-image-endpoint-signing.md)。
