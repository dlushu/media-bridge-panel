# ADR-0015 源包的两道 md5 校验

- 状态：已采纳
- 相关：[fetcher.js](../../server/modules/source/fetcher.js) · [0016](0016-source-auto-update-default-off.md)

## 背景

面板会下载第三方源包（`index.js`）并在本机以子进程方式运行。
该子进程可以读取自己的 `runtime/` 目录，其中可能包含网盘 cookie 或 token
（例如源的登录态）。因此"下载到一半的包"或"被修改过的包"一旦启动，风险由部署者承担。

## 决定

设两道校验：

1. **下载 / 更新之后**（`fetcher.download`）：下载得到的 `index.js` 必须与官方 `index.js.md5` 一致。
   **不一致、或该地址根本没有提供 md5，则删除本次下载的残留文件并如实回报失败** ——
   不使用实际值覆写 md5 来"假装成功"。新增源时连同源记录一起删除并返回 `400`；
   更新时清空源文件且不重启。
2. **运行之前**（`fetcher.verifyBundle`）：`index.js` 必须与 `index.js.md5` 一致，
   缺 md5 或对不上则**拒绝启动**，并提示先执行「更新」。
   `index.config.js` 的那一对校验规则为"存在就校验、缺失不拦" ——
   它在本地运行时不被读取，且部分源远端本就不提供。

## 理由

源包会以子进程运行并可能接触凭证。下载不完整或被修改的包不应被静默启动；
"用实际值覆写 md5"会让校验永久失去意义。

## 备选方案

- **只在下载时校验**：文件在磁盘上仍可能被改动，运行前不再校验。
- **不校验**：对第三方包而言等于没有信任边界。

## 后果

- 源地址必须提供 md5 文件，否则无法新增或更新该源。
- 用户遇到"拒绝启动"时的正确动作是重新点「更新」，而不是绕过校验。
- 校验失败时源会处于"文件不完整/未下载"状态，面板如实报告，不代为恢复。
