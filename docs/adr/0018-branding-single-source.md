# ADR-0018 产品名只在一处定义

- 状态：已采纳
- 相关：[server/core/branding.js](../../server/core/branding.js) · [public/core/branding.js](../../public/core/branding.js)

## 背景

产品名曾散落在多处：启动横幅、网页标题、登录页、顶栏、包名、请求 UA、
Emby 客户端显示的服务器名、文档。改名需要在整个仓库里搜索替换，必然遗漏。

## 决定

**产品名只在两处定义**：`server/core/branding.js` 与 `public/core/branding.js`（两份内容成对）。
其余位置一律读取它：启动横幅、请求 UA、登录页标题、顶栏、网页标题、Emby 默认服务器名。
`public/index.html` 中的标题与顶栏文本只是首屏兜底，启动后由前端覆盖。

字段含义：

| 字段 | 用途 |
|---|---|
| `name` | 产品短名 —— 包名、请求 UA、客户端服务器名 |
| `panelName` | 界面称呼 —— 网页标题、顶栏、登录页、启动日志 |
| `embyServerName` | Emby 客户端「服务器列表」中显示的默认名 |
| `slug` | 打包与镜像名 |

**部署标识不属于产品名**，不随改名变化：容器/服务名、数据卷名、登录 cookie 名、
前端 `localStorage` 键、备份文件名前缀。它们是"这套部署的身份"，改动会导致需要重新部署、
或让已登录的用户掉线。

## 理由

- 改名成本从"全仓库搜索替换"降为"改两个文件"。
- 三类名字的受众不同：UA 与包名要短、界面称呼要完整、客户端服务器名要在小尺寸界面里可读，
  因此需要分别定义而不是共用一个字符串。

## 备选方案

- **单一常量**：界面称呼与客户端服务器名会被迫相同，其中一处必然不合适。
- **各处写字面量**：即本 ADR 之前的做法。

## 后果

- 新增面向用户或外部的文本时，读取 branding，不写死字面量。
- 改名步骤：修改两份 branding（若同时改包名，再更新 `package.json` 的 `name`），
  `index.html` 中的兜底文本可选。
