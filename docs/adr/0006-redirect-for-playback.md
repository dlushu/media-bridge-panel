# ADR-0006 播放一律 302，不代理流量

- 状态：已采纳（取代早前的"面板代理 / 跳转"双模式）
- 相关：[emby-compat.md](../emby-compat.md) · [emby/service.js](../../server/modules/emby/service.js)

## 背景

播放端点有两种实现方式：面板把源返回的字节流接过来再转发给客户端（代理），或返回 `302` 让客户端
直接去源取流（跳转）。早期实现两种模式都保留，由设置项 `play.mode` 选择。

面板通常运行在路由器或低功耗小主机上，而代理模式意味着每条流的全部字节都要经过面板转发。

## 决定

**一律 `302` 跳转**到源提供的直链，删除代理模式与 `play.mode` 设置。

配套处理：

- 源返回的 `play.header` 非空时，客户端跳转后无法携带这些请求头 —— **如实记录一行日志**，不做伪装。
- 源按"谁访问它"回填 host，而聚合层是从 `127.0.0.1` 请求它的，因此源可能返回回环地址。
  跳转前若地址**确实是回环地址**，替换为「客户端访问面板所用的地址 + 源端口」；
  真实直链不做替换；自定义源（位于其他机器）一律原样返回。
- 源只返回相对地址时，按「同域名 + 源端口」补全。

## 理由

- 面板不做流量中转，带宽走客户端到源的最短路径。
- 省掉面板上最昂贵的一类开销（长连接 + 字节转发），对低功耗设备意义最大。

## 备选方案

- **保留代理模式**：某些源的线路必须带特定请求头才能播时，代理是唯一的兜底手段；
  但代价是把面板变成流媒体中转站，与运行环境不匹配，故不保留。

## 后果

- 源子进程监听的端口（默认 `9988-9998`）必须对客户端可达；容器部署时需要发布这些端口。
- 需要外网访问时，只发布面板端口（`8099`）并置于反向代理之后。
- 这些源端口没有鉴权，只应暴露在受信任的网络内。
