# ADR-0005 接续补打：最多试 N+K 条，凑够 N 条即止

- 状态：已采纳（**触发条件、停止条件与上限口径已被 [0027](0027-extra-fetch-only-when-zero.md) 取代**，
  其余部分继续有效）
- 相关：[agg/service.js](../../server/modules/agg/service.js) · [0003](0003-local-title-scoring.md) · [0004](0004-no-same-site-dedup.md) · [0027](0027-extra-fetch-only-when-zero.md)

## 背景

"命中"不等于"可播"。按分数取前 `matchMaxItems`（记为 N）条去请求站源 `/detail` 之后，可能出现
一条可用条目都没有的情况：条目没有线路（空壳），或有线路但没有定位到请求的那一集。
此时客户端的版本列表为空，而真正可用的条目可能排在 N 名之外 —— 被"最多保留条数"截掉了。

## 决定

先取前 N 条并发请求详情；若可用条目不足 N，则按分数**继续向后请求详情，最多再试 `matchExtraK`（记为 K）条，
一旦凑够 N 条立即停止**。K 填 `0` 表示不补打。另有开关 `matchExtraAll`（"匹配到底"）：
忽略 K，继续请求直到凑够 N 条或候选名单结束。

"可用"的判据：**有线路，且请求带集号时至少有一条线路定位到了该集**。
计数单位是**条目**（一个 `vod_id` 计一条），不是站点 —— 同一站点可以有多条条目各带线路。

## 理由

- 目标是"取到 N 条能用的"，不是"取 N 条"。排在后面的条目可能才是唯一可用的。
- 计数按条目而非站点，与版本列表的实际来源一致（同一条目可以贡献多条线路，也可以一条都没有）。
- 命中判据与客户端过滤规则一致：客户端不会列出没有定位到该集的线路，因此这类条目不算可用。

## 备选方案

- **命中即止**：最早实现为"打到第一条可用就停"。它无法保证得到 N 条，与"希望有 N 个版本"的目标不符，已否决。
- **固定取 M 条**：M 与 N 无关联，取多了浪费请求，取少了仍可能不足。

## 后果

- 最坏情况下一次请求要多打 K 次站源 `/detail`（顺序执行，凑够即停，因此常态不产生额外请求）。
- 诊断字段：`stats.targetN` / `matchUsable` / `extraTried` / `usableExtra`，
  以及 `picked.matchedBy = 'score+extra'`（表示代表条目来自补打）。
- 「聚合参数」页提供 K 与"匹配到底"两个旋钮；K 较大或开启"匹配到底"时响应会明显变慢。
