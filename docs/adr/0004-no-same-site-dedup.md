# ADR-0004 同一站点内不做同名去重

- 状态：已采纳
- 相关：[match.js](../../server/modules/agg/match.js) · [0003](0003-local-title-scoring.md)

## 背景

同一个站点经常为同一部作品返回多条条目：标题相同，`vod_id` 不同（对应不同的分享链接或清晰度）。
"最多保留条数"（`matchMaxItems`）是有限预算 —— 每保留一条命中，后续就要多请求一次站源 `/detail` 取线路。
按这个预算，直觉做法是在同一站点内只保留分数最高的一条。

## 决定

**不做同站同名去重**。源返回几条就保留几条，只统计同名条数（`match.sameNameSameSite`）用于诊断。
跨站点同样不去重 —— 不同站点代表不同线路，正是版本列表存在的意义。

## 理由

多条同名条目各自对应独立的播放地址，**能否播放只有请求 `/detail` 之后才能确定**。
按分数只保留其中一条，会丢弃实际可用的条目 —— 这正是"同名却匹配到错误结果"的来源。
去重换来的是省一点请求，代价是可能没有版本可播，取舍不成立。

## 备选方案

- **同站同名只保留分数最高的一条**：早期实现过，因上述原因被否决。
- **按 `vod_id` 去重**：`vod_id` 本来就不同，去重不会生效。

## 后果

- 同站同名条目会占用"最多保留条数"预算。需要更紧的预算时，由用户调低该设置，
  或在「站点与参数」中取消勾选对应站点。
- 「聚合搜索」页的条目上会显示同名计数，便于判断某个站点挂了多少条同名。
