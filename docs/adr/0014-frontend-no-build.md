# ADR-0014 前端零构建

- 状态：已采纳
- 相关：[public/](../../public/) · [tools/check-syntax.js](../../tools/check-syntax.js)

## 背景

前端需要确定交付方式。常见选择是引入打包器（webpack / vite 等），
但本项目的运行环境是路由器与小主机，部署者往往只拿到源码目录或一个镜像。

## 决定

**零构建**：浏览器直接加载原生 ES module，没有打包步骤、没有第三方依赖、没有构建产物。
`public/` 目录本身即交付物，由面板的静态文件服务直接提供。
这也意味着**不允许引入需要编译的语法或框架**。

## 理由

- 部署者不需要 Node 工具链与网络访问即可运行。
- 配合 `node --watch`，"改完保存即生效"，开发与运行使用同一份文件。
- 容器镜像不需要构建阶段，镜像里只有源码。

## 备选方案

- **打包**：可以做压缩、tree-shaking 与兼容性降级，但引入工具链、构建产物与版本管理问题，
  与"零依赖、可直接部署"的目标冲突。

## 后果

- 只能使用浏览器当前支持的语法，不做转译。
- 前端是 ES module，而 `package.json` 未声明 `"type": "module"`，
  因此 `node --check public/app.js` 会按 CommonJS 解析并报错；
  语法检查脚本对 `public/` 下的文件改用 `.mjs` 临时文件检查
  （见 `tools/check-syntax.js`）。
- 大型依赖（若将来必须引入）需要在 CI 中一并说明其来源与加载方式。
